# Fashion Accessories — Hub 0.6.0.0

Open /shub → Fashion Accessories. The local database loads in bounded framework-thread batches and remains independent of other Hub utilities and Mount Collection. Names/icons and own-character unlocks come from the game. Search names/IDs/items/sources; sort by name/ID/patch. Collection totals, expansion groups and source coverage are explicit.

The dated metadata snapshot has 52 identities and source text for 51. The installed client remains authoritative for catalog inclusion and item/market relationships. Unknown metadata is displayed and never converted into locked/unavailable. Four pre-7.0 spectacle ornaments are excluded because they became Facewear. Mandragora Parasol's acquisition remains Unknown. Historical events, promotions, currency labels and store sources remain distinct.

Expand Source, expansion and availability filters for category, expansion, market eligibility, recorded store sources and current obtainability. Market eligibility does not establish current stock. Store classification means a recorded source, not a live sale assertion. Current availability requires separately dated official evidence with expiry; most entries remain Unknown.

## Identify a player

Enable Include fashion accessories in player identification on this page. The existing Mount preference remains independent on Mount Collection. Both options default OFF on new installs; an existing enabled mount preference is preserved.

Right-click another loaded player → **Sentinel Hub: Identify player**. One context subscription handles both modules. The action queues a fresh framework-thread read and opens the accessory entry, or the mounted entry when only a mount is identified. A result banner can open either entry. It explicitly distinguishes None active, disabled, unknown ID and unavailable actor. If no accessory is active, an older selected accessory is cleared. The banner is a click-time snapshot and clears on logout, character/territory change, all lookup options OFF or disposal. Mount-only mode keeps its prior mounted-player-only menu behavior.

Normal typed actor state is used; no hook, pattern scan, unmanaged setup call, equip/use action or target tooltip modification. Auto-umbrella preferences are never reported as active accessories. Transformed, loading, invalid or stale actors yield unavailable. A local appearance mod or suppressed rendering is not reverse-engineered.

## Short supervised acceptance

Update normally to **0.6.0.0**, retain existing settings, then:

1. Enable accessory identification and identify another player with a parasol, wings or pack active. Verify the resolved name/icon and ornament ID. Try both a parasol and wings if available.
2. Compare your own unlocked/locked status with the game's Fashion Accessories window. Inspect source/category, patch/expansion and known unlock item/market status. Check a familiar source such as Vermilion Paper Parasol (100,000-gil route) or Red Moon Parasol's historical event/store source.
3. Have the player remove the accessory and identify again. Expect None active, with no stale accessory detail presented as the current result. An unloading/zoning/transformed target should be unavailable rather than guessed.
4. With Mount lookup enabled, identify a mounted player. Correct Mount details should still open; with both enabled, only one Hub context action should appear. Reload Hub once; check no duplicate entry or effect on the other utilities.
5. At minimum width in your theme, expand all filters, scroll database/details and restore/minimize once. Controls remain reachable.

Return PASS/FAIL, Hub version/theme, accessory ID/type, any wrong icon/source/unlock, and untested steps. Do not purchase/equip/exchange anything through Hub; it has no such action.

Rollback: switch accessory identification OFF, or use prior immutable Hub 0.5.1.0. No external character/profile queries, saved collections, inventory movement or metadata download occurs during play. Source links open only on a click. Prior utility acceptance scopes remain unchanged.
